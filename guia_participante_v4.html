T0

Arquitectura y Data Fabric

⏱️ 8:35 – 9:45 📓 T0_arquitectura.ipynb
▼

🎯 Qué evalúa este track

Valida que la plataforma soporte una arquitectura basada en dominios de negocio (Data Fabric/Mesh), con productos de datos gobernados, interoperabilidad, linaje visual, trazabilidad y descubrimiento de activos de datos.

📋 Lo que vamos a ver

  • 13 dominios de negocio (schemas) que reflejan las áreas reales de CredibanCo
  • Creación de productos de datos gobernados con tags de dominio
  • Linaje visual (diagrama interactivo en la UI)
  • Control de versiones con Git/GitHub (promoción entre ambientes)
  • Métricas de calidad de datos nativas (Data Quality tab)

✅ Actividades

1 🖥️ Abrir T0_arquitectura.ipynb y ejecutar celda por celda.
2 👁️ Navegar al Explorer: Databases → CREDIBANCO_HOL — observa los 13 schemas (un dominio de negocio por cada uno).
3 🖥️ Ejecutar Bloque 2: Crear un producto de datos gobernado (vista + tag de dominio).
4 👁️ VER LINAJE: Databases → CREDIBANCO_HOL → PAGOS → Views → PRODUCTO_PAGOS_USER → pestaña Lineage. El diagrama visual muestra de dónde vienen los datos.
5 👁️ VER GIT: Projects → Workspaces — el repositorio está conectado a GitHub. Esto es control de versiones = promoción entre ambientes.

👁️ Dónde mirar en Snowsight

Linaje: En cualquier vista o tabla, la pestaña Lineage muestra un diagrama visual interactivo — haz click en cualquier nodo para ver el detalle.
Calidad: En cualquier tabla, la pestaña Data Quality muestra métricas nativas (frescura, completitud, validez) automáticamente.
Git: En Projects → Workspaces, el ícono de Git confirma la conexión al repositorio.

💡 Por qué importa para CredibanCo

La arquitectura de 13 dominios refleja las áreas reales de CredibanCo. Los productos de datos permiten que cada equipo publique y descubra datasets sin depender de TI — acelerando el acceso a información confiable.

T1

Gobierno y Zero Trust

⏱️ 9:25 – 10:35 📓 T1_gobierno.ipynb
▼

🎯 Qué evalúa este track

Valida gobierno de datos, seguridad Zero Trust, clasificación automática de información sensible, masking dinámico por rol, calidad nativa, linaje, auditoría y cumplimiento regulatorio (PCI-DSS, Habeas Data).

📋 Lo que vamos a ver

  • Masking dinámico: el mismo dato se ve completo o enmascarado según tu rol
  • Clasificación automática de PII — Snowflake detecta datos sensibles sin reglas manuales
  • Tags de gobernanza aplicados a tablas y columnas
  • Panel de Governance en la UI con todas las políticas en un solo lugar
  • Métricas de calidad de datos nativas

✅ Actividades

1 🖥️ Abrir T1_gobierno.ipynb y ejecutar celda por celda.
2 🖥️ Ejecutar la consulta con rol SEGURIDAD_INFO — verás los datos completos (PAN visible, cédula completa).
3 🖥️ Cambiar a rol NEGOCIO y ejecutar la misma consulta — ahora los datos sensibles están enmascarados (PAN tokenizado, cédula parcial).
4 🖥️ Ejecutar clasificación automática de PII — Snowflake detecta columnas con datos sensibles sin configuración manual.
5 👁️ VER GOBERNANZA: Databases → CREDIBANCO_HOL → CLIENTES → TARJETAHABIENTES → pestaña Governance. Aquí ves masking policies, tags PII y clasificación — todo en un solo lugar.
6 👁️ VER CALIDAD: En la misma tabla → pestaña Data Quality — métricas nativas de calidad de datos.

👁️ Dónde mirar en Snowsight

La pestaña Governance muestra TODAS las políticas, tags y clasificaciones en un solo lugar — no es necesario ejecutar queries para verlas. Es la forma más clara de verificar que el gobierno está aplicado.

💡 Por qué importa para CredibanCo

PCI-DSS y la Ley de Habeas Data exigen protección de PAN, cédula y datos personales. El masking dinámico garantiza cumplimiento sin impactar la operación — cada persona ve solo lo que su rol permite.

T2

Ingeniería de Datos

⏱️ 10:15 – 11:25 📓 T2_ingenieria.ipynb
▼

🎯 Qué evalúa este track

Valida capacidades de ingesta y transformación (batch, streaming, CDC), calidad embebida en pipelines, observabilidad, control de versiones y promoción de código entre ambientes de desarrollo, pruebas y producción.

📋 Lo que vamos a ver

  • Pipeline automatizado bronce → plata → oro (Dynamic Tables)
  • Propagación automática de cambios en tiempo real
  • Tablas Iceberg (formato abierto Apache Iceberg)
  • Ingesta desde API externa y configuración de Openflow (con CoCo)
  • dbt: modelos, tests y ejecución completa
  • Código versionado en GitHub

✅ Actividades

1 🤖 PRIMERO: Copiar el prompt de la celda 5 en Cortex Code (panel derecho) — esto lanza la ingesta de API + configuración Openflow en paralelo.
2 🖥️ Mientras CoCo trabaja, ejecutar Bloque 1: Ver el pipeline de Dynamic Tables (bronce → plata → oro).
3 🖥️ Ejecutar Bloque 2: Insertar un dato nuevo y ver la propagación automática (compara el conteo ANTES vs DESPUÉS).
4 👁️ VER LINAJE DEL PIPELINE: Databases → CREDIBANCO_HOL → PAGOS → DT_AUTORIZACIONES_SILVER_USER → Lineage — la cadena de transformación visual.
5 🖥️ Ejecutar Bloque 2A: Crear una Iceberg Table (formato abierto Apache Iceberg).
6 🖥️ Ejecutar SHOW ICEBERG TABLES — verificar la tabla en formato abierto.
7 🤖 Copiar prompt de dbt en CoCo — crea proyecto con modelos, tests y ejecuta dbt build.
8 👁️ VER GIT: Projects → Workspaces — el código está versionado en GitHub (= promoción entre ambientes).

👁️ Dónde mirar en Snowsight

Pipeline: El linaje de Dynamic Tables muestra la cadena completa de transformación bronce → plata → oro.
Refresh state: En la UI de cada Dynamic Table, el estado de refresh indica si el pipeline está al día.
Iceberg: La tabla aparece en el Explorer como cualquier otra, pero su formato interno es abierto.

💡 Por qué importa para CredibanCo

Los pipelines de autorizaciones y liquidaciones se actualizan solos — sin Spark, sin Airflow, sin operación manual. Cualquier cambio en la fuente se propaga automáticamente hasta las capas de consumo.

T4

Analítica, ML y GenAI

⏱️ 11:30 – 12:15 📓 T4_analitica_ia.ipynb + T4B_mlops.ipynb
▼

🎯 Qué evalúa este track

Valida el ciclo completo de MLOps y GenAIOps: gobierno de features, entrenamiento, registro de modelos, inferencia, monitoreo, observabilidad, trazabilidad, IA responsable (explicabilidad) y gestión de agentes conversacionales.

📋 Lo que vamos a ver

  • IA Generativa en SQL: extracción, clasificación y búsqueda semántica
  • RAG (Retrieval Augmented Generation) sobre documentos SARLAFT
  • Agente conversacional creado con CoCo
  • Ciclo MLOps completo: Feature Store → Training → Registry → Inference → Observabilidad → SHAP
  • Model Registry con versiones, métricas y alias de producción

⚠️ Este track tiene 2 notebooks

T4_analitica_ia.ipynb — IA Generativa en SQL (primero)
T4B_mlops.ipynb — MLOps completo (después)

✅ Actividades — T4: IA Generativa en SQL

1 🖥️ Abrir T4_analitica_ia.ipynb y ejecutar: AI_COMPLETE extrae campos de texto, AI_CLASSIFY categoriza alertas automáticamente.
2 🖥️ Ejecutar RAG: Cortex Search busca en documentos SARLAFT con lenguaje natural — como preguntarle a un experto regulatorio.
3 🤖 Copiar el prompt de Agente en CoCo — crea un agente conversacional SARLAFT que responde preguntas sobre regulación.

✅ Actividades — T4B: MLOps Completo

4 🖥️ Abrir T4B_mlops.ipynb — ejecutar el ciclo completo: Feature Store → Training → Registry → Inference → Observabilidad → SHAP (explicabilidad).
5 👁️ VER MODELO: Databases → CREDIBANCO_HOL → ANALITICA → Models → MODELO_FRAUDE_CREDIBANCO — versiones, métricas y alias "champion".
6 👁️ VER FEATURE STORE: Databases → CREDIBANCO_HOL → ANALITICA → Feature Views — features registradas con descripción y estadísticas.

👁️ Dónde mirar en Snowsight

Model Registry: Muestra versiones, métricas comparativas y alias de producción ("champion").
Feature Views: Muestra las features registradas con su descripción y estadísticas.
SHAP: Los gráficos de explicabilidad se ven directamente en el notebook.

💡 Por qué importa para CredibanCo

El modelo de fraude se entrena, registra y ejecuta donde viven los datos — sin sacarlos de Snowflake. Cumple con el perímetro de seguridad exigido y permite explicar cada predicción (IA responsable).

▼

🎯 Qué evalúa este track

Valida descubrimiento de datos, autoservicio para usuarios de negocio, consultas en lenguaje natural (español), experiencia de usuario, autonomía analítica y capacidad de compartir datos sin dependencia del proveedor.

📋 Lo que vamos a ver

  • Catálogo de productos de datos y sandboxes de análisis
  • Cortex Analyst: preguntas en español → SQL automático
  • App interactiva de BI creada con CoCo (Streamlit)
  • Data Sharing: compartir datos sin copias (zero-copy)
  • Marketplace interno: publicar y descubrir productos de datos

✅ Actividades

1 🖥️ Abrir T6_autoservicio_bi.ipynb y ejecutar Bloque 1: Ver sandboxes y catálogo de productos de datos.
2 🖥️ Ejecutar query de negocio: top regiones por categoría de transacción.
3 🖥️ Ejecutar Cortex Analyst: Crear Semantic View + hacer pregunta en español → Snowflake genera el SQL automáticamente.
4 🤖 Copiar prompt de Streamlit en CoCo — crea una app interactiva de BI con filtros, gráficos y tablas.
5 👁️ VER STREAMLIT: Projects → Streamlit → abrir la app creada. Interactúa con los filtros y gráficos.
6 🖥️ Ejecutar Bloque 2B: Crear un share con 3 tablas (zero-copy data sharing — sin copiar datos).
7 👁️ PUBLICAR LISTING: Data Sharing → Internal Sharing → + Create Listing → seleccionar CREDIBANCO_PAGOS_SHARE.
8 👁️ VER MARKETPLACE: Data Sharing → Internal Marketplace → buscar "CredibanCo" — el producto aparece disponible para toda la organización.

👁️ Dónde mirar en Snowsight

Streamlit: La app se abre en una pestaña dentro de Snowsight — es una aplicación web completa con filtros interactivos.
Marketplace: El Internal Marketplace funciona como un catálogo de productos de datos — cualquier área puede descubrir y solicitar acceso sin tickets de soporte.

💡 Por qué importa para CredibanCo

Los analistas de negocio hacen preguntas en español, ven dashboards interactivos y publican datos — todo sin escribir código y sin depender del equipo de datos. Es autoservicio real.

🎯 Qué evalúa este track

Valida observabilidad, monitoreo, FinOps (control de costos), presupuestos, diagnóstico proactivo, mejora continua y automatización — todo operado en lenguaje natural a través de Cortex Code.

📋 Lo que vamos a ver

⚠️ Este track es 100% con Cortex Code

✅ Actividades

1 🖥️ Abrir T7_dataops_finops.ipynb — ejecutar SOLO la celda de contexto (USE ROLE).
2 🤖 Prompt 1: "Muéstrame el consumo de créditos desglosado por servicio"
3 🤖 Prompt 2: "Tendencia diaria de consumo con picos anómalos marcados"
4 🤖 Prompt 3: "Top 10 queries más costosas de la semana"
5 🤖 Prompt 4: "Reporte de chargeback por dominio de negocio"
6 🤖 Prompt 5: "Configurar Resource Monitor con límite de 100 créditos"
7 🤖 Prompt 6: "Detectar anomalías en el gasto con Z-Score"
8 🤖 Prompt 7: "Dashboard FinOps ejecutivo en Streamlit"

👁️ Dónde mirar en Snowsight

Streamlit: El dashboard FinOps que CoCo crea se abre en Projects → Streamlit.

💡 Por qué importa para CredibanCo

El equipo de infraestructura y finanzas puede monitorear costos, atribuir consumo por área (chargeback) y detectar anomalías — todo en lenguaje natural, sin necesidad de escribir SQL.
