1. Resource Monitors devuelve "Page not found"

P0 — antes del evento
Bloquea: H25, H29 · Afecta a cualquier perfil de usuario, no solo no técnicos
Evidencia
En la sesión de browser, Admin > Cost Management > Resource Monitors devuelve "Page not found" de forma reproducible, tanto navegando por URL directa como haciendo clic desde el menú lateral (esto último descarta que sea solo un problema de "refresh").
Causa raíz confirmada

No es un problema de datos ni de permisos. Verificación vía SQL directa (rol ACCOUNTADMIN, sin pasar por la UI):

SHOW RESOURCE MONITORS;
Resultado: existen 2 resource monitors, ambos bien configurados:
MONITOR_CREDIBANCO — credit_quota=100, notify_at 75%/90%, frequency MONTHLY
RM_HOL_CREDIBANCO — credit_quota=100, notify_at 75%/90%, frequency MONTHLY (coincide exactamente con lo que promete el deck para H25/H29)

Conclusión: es un bug de routing/SPA de Snowsight en esta build, no algo que se arregle regenerando el HOL ni cambiando permisos.

Fix recomendado (pasos)
  1. Reproducir el error en una ventana de incógnito / sesión nueva, para descartar caché de browser como causa.
  2. Reproducir explícitamente con el rol ACCOUNTADMIN ya seleccionado (no con el default actual) para descartar que sea un tema de rol.
  3. Abrir la consola de desarrollador (F12) al momento del error y capturar la URL exacta que falla (ej. algo como .../resource_monitors?preset=...) y el mensaje de red/consola — esto es lo que necesita soporte de Snowflake para diagnosticar.
  4. Si persiste, abrir un caso de soporte / reportarlo al equipo de Snowsight, referenciando: cuenta otc03722 (región us-east-1, alias LEDZYD), página Cost Management > Resource Monitors, error "Page not found" reproducible por menú y por URL.
  5. Plan B para el día del evento si no se resuelve a tiempo: tener listo un worksheet con SHOW RESOURCE MONITORS; para mostrar los thresholds 75%/90%/100% vía SQL como respaldo de H25/H29, y avisar al facilitador de antemano.
Cómo verificar que quedó resuelto

Navegar a Admin > Cost Management > Resource Monitors desde el menú lateral (no por URL pegada) y confirmar que se listan MONITOR_CREDIBANCO y RM_HOL_CREDIBANCO con sus thresholds visibles en la UI, no solo por SQL.

2. Rol default incorrecto en la cuenta LEDZYD

P0 — antes del evento
Afecta el primer minuto de cualquier evaluación en esta cuenta específica
Evidencia
Al iniciar sesión en credibanco-hol (LEDZYD), el rol activo por defecto es OPENFLOW_ADMIN_RL, no ACCOUNTADMIN. El deck y la guía asumen ACCOUNTADMIN desde el inicio. Con OPENFLOW_ADMIN_RL, varias vistas (Catalog, AI & ML, Governance) pueden aparecer vacías o incompletas, y una usuaria no técnica no sabrá que debe cambiar de rol.
Causa raíz + alcance real (verificado en las 9 cuentas disponibles)

Se ejecutó DESCRIBE USER "USER"; vía SQL en las 9 cuentas HOL configuradas para este RFP. Resultado:

Nota: CRB_HOL_ADMIN es un rol construido específicamente para el HOL (tiene CREATE ORGANIZATION LISTING, CREATE SHARE, APPLYBUDGET sobre CREDIBANCO_HOL, entre otros) y está asignado a usuarios nombrados como CRB_EXPERIENCIA, CRB_USER_5. Si este rol tiene todos los privilegios que necesita el deck (lectura de Catalog, Governance, AI & ML, Cost Management), es una alternativa válida a ACCOUNTADMIN y no requiere cambio. El único problema real y confirmado es la cuenta LEDZYD.

Fix exacto (SQL)
-- Ejecutar en la cuenta credibanco-hol (LEDZYD) con un rol que tenga permiso para alterar el usuario:
USE ROLE ACCOUNTADMIN;
ALTER USER "USER" SET DEFAULT_ROLE = ACCOUNTADMIN;

-- Verificación inmediata:
DESCRIBE USER "USER";
-- Confirmar que la fila DEFAULT_ROLE ahora dice ACCOUNTADMIN
Fix complementario (guía, si no se puede tocar la cuenta a tiempo)

Agregar un "Paso 0" explícito en guia_participante_v4.html y guia_facilitador_v4.html: "Antes de empezar, verifica que el rol activo (esquina superior derecha) diga ACCOUNTADMIN. Si dice otra cosa, haz clic ahí y selecciónalo."

Cómo verificar que quedó resuelto

Cerrar sesión y volver a entrar con USER / sn0wf@ll en LEDZYD; el rol mostrado en la esquina superior derecha debe decir ACCOUNTADMIN sin necesidad de cambiarlo manualmente.

3. Data Metric Function sin resultados recientes (H05)

P0 — antes del evento
Afecta: Data Quality tab de PAGOS.AUTORIZACIONES
Evidencia
El Data Quality tab de PAGOS.AUTORIZACIONES muestra la asociación DMF_MONTO_VALIDO ↔ columna MONTO, pero reporta "0/1 association passing" y "1 with no checks" — el DMF está bien asociado pero no tiene evaluaciones recientes que mostrar. Para una evaluadora esto puede parecer que la feature "está rota".
Causa raíz

El schedule de evaluación del DMF sobre esta tabla está en DATA_METRIC_SCHEDULE = 60 MINUTES (confirmado vía SHOW PARAMETERS IN TABLE). Si no ha pasado un ciclo completo desde que se asoció el DMF, o si no hubo cambios en los datos, no hay resultados que mostrar todavía.

Fix recomendado (dos opciones)
  1. Opción rápida — forzar una evaluación inmediata: cambiar temporalmente el schedule a evaluación por cambios y generar un DML trivial para dispararlo: 
    ALTER TABLE CREDIBANCO_HOL.PAGOS.AUTORIZACIONES
  SET DATA_METRIC_SCHEDULE = 'TRIGGER_ON_CHANGES';

-- Disparar una evaluación con un cambio mínimo (ejemplo, ajustar a un ID real que no altere el demo):
UPDATE CREDIBANCO_HOL.PAGOS.AUTORIZACIONES
  SET MONTO = MONTO
  WHERE FALSE; -- reemplazar por una condición que sí afecte al menos 1 fila si no dispara

-- Volver al schedule original si se prefiere mantenerlo en 60 minutos:
ALTER TABLE CREDIBANCO_HOL.PAGOS.AUTORIZACIONES
  SET DATA_METRIC_SCHEDULE = '60 MINUTES';
  2. Opción simple — esperar el schedule: si se hace la preparación con suficiente margen antes del evento (más de 60 minutos), no se necesita ninguna acción — el schedule existente eventualmente genera al menos una evaluación.
Cómo verificar que quedó resuelto

Ir a Catalog > Explorer > PAGOS > AUTORIZACIONES > Data Quality tab y confirmar que DMF_MONTO_VALIDO muestra al menos 1 evaluación con resultado (pass o fail), en vez de "no checks".

5. Ruta a CoWork con salto adicional no documentado

P1 — importante
Archivo: credibanco_overview_deck.html · Sección T4
Evidencia
El deck dice ir a "AI & ML" / "Snowflake Intelligence (CoWork)" como si fuera un único ítem de sidebar. En la UI real, el ítem "AI & ML" del sidebar lleva directamente a "Agent Studio" (página de administración de agentes). Para usar un agente (hacerle una pregunta) hace falta un paso adicional: un enlace/botón separado "Snowflake CoWork" que abre una app distinta (ai.snowflake.com). Riesgo: una evaluadora se queda en la vista de administración sin darse cuenta de que debe cruzar a otra URL.
Fix exacto (texto sugerido para el deck)
Ir a: AI & ML > Agent Studio (para ver y administrar los agentes)
Para conversar con un agente: buscar el enlace/botón "Snowflake CoWork"
(abre una app separada en ai.snowflake.com) y seleccionar el agente ahí.

Aplicar este texto en las tarjetas H15, H19 y H20 del tab T4, donde actualmente se asume un solo paso.

Cómo verificar que quedó resuelto

Seguir el texto actualizado del deck sin conocimiento previo de la UI y confirmar que efectivamente se llega a poder chatear con un agente sin quedarse atascado en Agent Studio.
