1. Cambio de Formato V3 → V4

V3 (anterior)

  • HTMLs externos (copy-paste al worksheet)
  • Tracks de 50-75 min
  • Context switch: browser + Snowsight
  • ~30s por bloque SQL (copiar, pegar, ejecutar)

V4 (actual)

  • Notebooks DENTRO de Snowsight (zero copy-paste)
  • 15 min por persona, ~12 celdas Run
  • Todo en una sola pestaña
  • ~2s por celda (click Run, ver resultado)
  • Git sync: cambios se propagan al instante
Regla de oro “Si el proveedor ejecuta la tarea por el usuario, la actividad no se considera autónoma.” — Toda ayuda se registra. El facilitador guía, NO ejecuta.

3. Cómo Abrir un Notebook (instrucción para participantes)

Paso a paso
  1. Abrir Snowsight → Projects → Notebooks
  2. Seleccionar el notebook de su track (ej: T1_GOBIERNO)
  3. Ejecutar celda por celda con Shift+Enter o botón Run
  4. Los resultados aparecen inline debajo de cada celda
  5. Las celdas Markdown tienen las instrucciones y el prompt CoCo

6. Estructura de Cada Notebook (15 min)

Bloque 1 (5 min) — EVIDENCIA: El participante ve con SHOW/SELECT lo que ya existe pre-creado. No crea nada, solo verifica que funciona.
Bloque 2 (5 min) — EJECUTAR: El participante crea algo real con 1-2 queries SQL.
Bloque 3 (5 min) — COCO: El participante copia un prompt a Cortex Code y ve cómo la IA genera algo complejo en 30 segundos.

Esta estructura demuestra los 3 lentes de evaluación: Capacidad demostrada (B1), Autonomía del usuario (B2), UX y productividad (B3/CoCo).

7. Git Sync — Actualizaciones en Vivo

Flujo de actualización Si necesitas corregir algo durante el evento:
git push desde tu laptop → En Snowsight ejecutar ALTER GIT REPOSITORY HOL_REPO FETCH; → Los notebooks se actualizan al instante.

8. Troubleshooting Rápido

ProblemaSolución
“No veo el notebook”Projects → Notebooks → buscar por nombre. Si no aparece, verificar rol activo con SELECT CURRENT_ROLE()
“Object does not exist”La primera celda del notebook ejecuta USE ROLE/DATABASE/WAREHOUSE. Ejecutarla primero.
“Insufficient privileges”Verificar que esté con el rol correcto del track. Los notebooks corren con ACCOUNTADMIN como owner.
CoCo no respondeVerificar que el rol tenga CORTEX_USER. Todos los roles del HOL ya lo tienen.
Notebook no cargaFallback: abrir un SQL Worksheet y copiar las queries de la guía HTML V3.
Cortex Search tardaNormal en la primera indexación (~30 seg). Ya está pre-indexado, debería ser instantáneo.

9. Qué Hacer y Qué NO Hacer

SÍ

  • Explicar QUÉ hace cada celda antes de que la ejecuten
  • Señalar el prompt CoCo como alternativa
  • Dejar que exploren libremente después de los 3 bloques
  • Tomar nota de preguntas para responder al final
  • Si alguien termina rápido: “prueba el prompt CoCo del bloque 3”

NO

  • Ejecutar celdas en el computador del participante
  • Saltar bloques para “ahorrar tiempo”
  • Comparar explícitamente con Databricks
  • Decir “esto no funciona en DBX”
  • Abrir HTMLs externos (todo está en los notebooks)

11. Benchmarks vs Databricks (NDA — NO compartir)

Solo para contexto interno del facilitador
  • Analytics (TPC-DS Iceberg): Snowflake 1.9-2.1x más rápido
  • AI Training (XGBoost): Snowflake 2.3x más rápido
  • DML/MERGE: Snowflake 1.9-2.2x más rápido
  • Transaccional (Postgres): Snowflake 4x mejor concurrencia
  • Inference: Snowflake 3x menor latencia, 0% error vs 83.5% DBX

Fuente: MCG Benchmark Report 2026 (Seismic). Estos números NO se mencionan al cliente — la evidencia habla sola en el HOL.
